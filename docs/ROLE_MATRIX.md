# HafaPass role matrix

Generated by `hafapass_api/script/generate_role_matrix.rb`. Do not edit the table by hand.

Permissions come from [OrganizationAuthorization](../hafapass_api/app/services/organization_authorization.rb); role labels and access notes come from [OrganizationRoles](../hafapass_api/app/services/organization_roles.rb). Row mappings live in [OrganizationRoleMatrix](../hafapass_api/app/services/organization_role_matrix.rb). The Settings comparison and role pickers share the [generated JSON](../hafapass_frontend/src/generated/roleMatrix.json).

Organization roles apply across the organization, except Box office and Door scanner, which require assigned events. Event managers have access to their assigned events only; creating, copying and repeating events requires an organization Manager or Owner role.

This table describes role permissions for active memberships. Event lifecycle, verification, launch capabilities, inventory and payment controls still apply. It does not grant access or override the backend checks.

## Access notes

- Managers can't cancel events or move money.
- Finance sees buyer contact details in refunds and finance exports, but does not get the attendee contact list.
- Event assignments add access for this event only.
- Scanner phones that are offline keep working until they reconnect or for up to 24 hours. Removing access stops them as soon as they reconnect.
- **Create, edit & publish events:** Event managers can edit and publish assigned events; creating events requires an organization Manager or Owner role.
- **Edit event page content only:** Marketers can change page content, but cannot publish events or change their schedule.
- **Copy/repeat events:** Event assignments do not allow creating, copying or repeating events.
- **See attendee names & emails:** Finance sees buyer contact in refunds and finance exports. Scanners see admission names, not email addresses.
- **Finance reports & sales exports:** Box office can export attendee sales data for assigned events, without financial amounts.
- **Promo codes, promoters & buyer emails:** Buyer emails means sending campaigns; it does not grant the attendee contact list.
- **Assign staff to events:** Event managers can assign door staff on their events. Organization-wide invitations and role changes require the Owner.
- **Organization profile & verification:** Owners manage the profile and submit verification; HåfaPass controls verification approval.
- **View activity log (all / events / money):** Event activity for event managers is limited to assigned events.

## Keeping the matrix current

After changing authorization permissions, assignment scopes, labels or row mappings, run these commands from the repository root:

```sh
ruby hafapass_api/script/generate_role_matrix.rb
ruby hafapass_api/script/generate_role_matrix.rb --check
```

The Ruby contract spec checks both generated files against the backend, including all organization and event-assignment permission grants. The focused Vitest tests check the frontend label contract, desktop columns and selected-role mobile lists, and opening/closing the comparison without changing an invite draft or a teammate's role.

Activity categories are read from `view_activity_all`, `view_activity_events` and `view_activity_finance`. A category appears only when the backend grants it; adding those permissions requires regeneration.
